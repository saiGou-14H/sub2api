# WebCodex V6 开发进度快照索引

本目录保存用户要求纳入 Git 的开发进度记录。它是跨仓库项目的进度快照，不替代包参考、源码或 V6 架构。核对日期和行为基线见状态总表，docs 提交不增加功能完成数。

- [开发状态总表](./WEBCODEX_V6_DEVELOPMENT_STATUS.zh-CN.md)：最新范围、十个功能提交、逐项待办、优先顺序和当前限制。
- [实施进度与验证回执](./WEBCODEX_MIGRATION_PROGRESS.zh-CN.md)：各阶段代码与测试证据。
- [工程评估及历史快照](./WEBCODEX_V6_PROGRESS_ASSESSMENT.zh-CN.md)：约 15% 的估算口径；第 1～8 节是历史状态，第 9～11 节记录后续实现。
- [来源及校验清单](./manifest.json)：根目录源文件与本仓库版本的 SHA-256、代码基线及外部工作区引用。

本地工作区根同时保留上述三份源文档。两个开发仓库都保存完整进度记录，内容事实一致；仅同仓库源码链接根据位置重定位，另一仓库／冻结源码／外部设计文件以明确工作区路径列出，独立 clone 不自动包含它们。源文件与镜像散列不同通常源于这些引用转换；manifest 可核对具体内容。

维护入口是工作区根的 `sync_webcodex_progress.py`。先更新并审阅根目录三份文档，再在该工作区执行以下命令；不访问网络或执行模型、也不自动提交／推送。

```sh
python3 sync_webcodex_progress.py --write
python3 sync_webcodex_progress.py
```

脚本只写本目录三个具名进度文件、该索引和 manifest，检查两个分支与代码基线，拒绝丢失的来源或失效的文件引用；默认仅核验。脚本不会写产品源码、覆盖日志、部署服务或自动同步。完成文档 diff 审查后在各仓库创建本地 docs 提交。
